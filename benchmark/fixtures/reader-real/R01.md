## What changed

- **Preferences file:** `bro-preferences.md` is added to every explain, Show and BTW prompt, quoted and labelled, alongside Bro's own instructions. The advisor never gets it.
- **What preferences can change:** wording, tone, technical depth and answer language. Code, commands, paths, names and numbers always stay exactly as written. In Show, preferences only change wording and language.
- **What always wins:** per-run choices (the mode, **M**, a Show steering query, the BTW question) beat standing preferences. Bro's source rules, Show's drawing rules and BTW's access mode always apply.
- **Old file:** `bro-prompt.md` is no longer read, with no migration. Modes and **M** now always work.
- **`/bro preferences`:**
  - Opens with your default text (the version of your `bro-prompt.md` from earlier), marked "not saved". Ctrl+S saves it and Esc leaves no file.
  - Refuses to save over 4,000 characters, and a file that's too long still opens so you can trim it.
  - Ctrl+K deletes the file.
  - `/bro advisor-steer` uses the same editor and behaves as before.
- **Header tag:** shows `· prefs` when preferences shaped a result. `/bro open` keeps the tag; **R** and **M** re-read the file.
- **BTW:** if preferences change mid-thread, the next question starts a fresh backend session that's caught up on the thread, on every backend, so old preferences don't linger.
- **Too-long file:** a file over 4,000 characters stops explain, Show and BTW with a clear error before anything is sent. Doctor reports it, and Help still opens and shows the problem.
- **Docs:** README, `/bro help`, `docs/DEVELOPMENT.md`, `docs/TESTING.md`, `benchmark/README.md` and the CHANGELOG are updated, the design doc is included, and the version is bumped to 0.21.0.

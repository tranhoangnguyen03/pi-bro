## Must fix

### 1. Captured code can silently change
**`review-source.ts:59`**

The backend checkout shares the captured Git object store. Git replacement refs created inside that checkout also affect `readEvidence`.

**Confirmed:** after replacing a Git blob in a temporary checkout, the supposedly captured evidence displayed `"forged"` instead of the original content.

**Fix:** disable replacement-object lookup for authoritative capture/evidence reads and add a regression test. This protects evidence identity without introducing a new permission framework; full-access execution still isn’t a sandbox.

### 2. One damaged review blocks the entire resume list
**`review.ts:77–81`**

`listReviews` stops at the first unreadable record. One corrupt JSON file prevents you from selecting any healthy saved review.

**Fix:** isolate failures per record, keep valid reviews selectable, and visibly report which records could not be loaded. Leave damaged files untouched.

### 3. Interrupted capture can leave retry stuck
**`review-source.ts:52`**

A partially populated checkout without a valid `.git` link causes subsequent capture attempts to fail with “already exists.”

**Confirmed:** a nonempty incomplete checkout reproduced the failure. An empty directory did not—the report’s original example was too broad.

**Fix:** safely recover incomplete managed captures and verify checkout completeness before reusing them.

## Should fix

### 4. New guides inherit the old Overview’s scroll position
**`review.ts:25–29`**

Opening a brand-new guide carries over `overview:reading:` from the previous guide. It can open halfway down rather than at its beginning.

**Confirmed:** an old Overview offset of 8 became the new guide’s offset.

**Fix:** start a new guide’s Overview at zero; retain saved positions when returning to an existing version.

### 5. Interrupted answers can falsely appear active
**`review-modal.ts:256`**

Discussion status uses the modal-wide `busy` flag. Starting regeneration—or answering another question—makes older interrupted answers display “In progress” or “Working…”

**Fix:** tie activity indicators to the actual running turn, not any running operation.

### 6. A failed regeneration hides an already-ready guide
**`review-modal.ts:310–312`**

If regeneration A succeeds but remains unopened, then regeneration B fails, the header shows only the failure. Overview still offers **Open new guide**, so the status and available action disagree.

**Fix:** keep the saved pending guide prominent while reporting the later failure separately.

### 7. Doctor misses review-only backend selections
**`bro.ts:361–365`**

The backend-probe checks omit the `review` capability. A backend used only for Guided Review may be reported as unused and never checked.

**Fix:** derive backend usage from the capability list rather than repeating individual feature names.

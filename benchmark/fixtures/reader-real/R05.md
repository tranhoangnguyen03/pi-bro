Use a **disposable working directory and load this checkout explicitly**, so you don’t accidentally test the installed Bro version.

## 1. Start local Pi with this checkout

Run in a new terminal:

```bash
BRO="/path/to/pi-bro"
TEST="$(mktemp -d /tmp/bro-guided-review.XXXXXX)"

printf 'Leave this file unchanged\n' > "$TEST/canary.txt"
cd "$TEST"

gh auth status

pi --no-extensions \
  -e "$BRO/bro.ts" \
  --no-skills \
  --no-prompt-templates \
  --no-context-files \
  --session "$TEST/session.jsonl"
```

This loads only the local Bro extension. It still uses your normal Bro settings and backend credentials.

Inside Pi:

```text
/bro config
```

Choose your preferred backend/model for **Guided review**. Guide generation and questions will make real backend calls.

## 2. Open a PR and inspect the captured changes

Use the public PR already checked during development:

```text
/bro guided-review https://github.com/tranhoangnguyen03/pi-bro/pull/102
```

**Expected:**
- PR identity appears while source is fetched.
- The review opens with repository, PR number, captured head, base, and comparison revision.
- Your active workspace is not switched to the PR.
- Opening the PR does **not** automatically generate a guide.

### Current keyboard controls

Focus starts in the question composer. **Tab** cycles through:

| Position | Control | Action |
|---|---|---|
| 0 | Question composer | Type; Enter sends |
| 1 | Guide / Changes | Enter switches view |
| 2 | Next topic | Enter advances |
| 3 | Evidence | Enter opens evidence selection |
| 4 | Generate/retry | Enter generates the initial guide |
| 5 | Scroll body | ↑/↓ scroll; ←/→ move horizontally in code |
| 6 | Question target | Enter switches topic / whole review |

**Shift+Tab** moves backward. The focused control is bracketed.

From the initial composer:
1. Press **Tab, Enter** to open Changes.
2. Tab to **Scroll body**.
3. Try vertical scrolling and horizontal scrolling on long lines.

**Expected:** actual unified diff and changed-file inventory, not a model’s summary.

## 3. Generate the guide

Focus **Generate/retry**, then press Enter.

From the initial composer position, that is **four Tabs, then Enter**.

**Expected:**
- A working notice appears.
- A summary and behavior-oriented topics appear when generation completes.
- Source references are listed; invalid ones are labelled unresolved.
- The footer reports **Saved**.

If generation fails, capture the error text. Changes should remain usable, and Generate/retry should allow another attempt.

## 4. Ask a topic question

Switch back to Guide if necessary. Choose a topic with **Next topic**.

Return focus to the composer and ask:

```text
Explain the behavior this topic changes and one thing the evidence does not establish.
```

**Expected:**
- The answer addresses the selected topic.
- It appears beneath that topic without replacing the original explanation.
- Typing letters such as `n` does not navigate.
- The completed answer is saved.

Then focus the question-target control, switch to **whole review**, and ask:

```text
What should I understand first before reviewing this PR?
```

## 5. Inspect and ask about evidence

1. Choose a topic with a resolved reference.
2. Focus **Evidence**, then Enter.
3. Select a reference if there is more than one.
4. Accept or enter a line range such as `10-20`.
5. Return to the composer and ask:

```text
Explain these selected lines and how they relate to the change.
```

**Expected:**
- Numbered captured source appears with surrounding context.
- The question target says **selected evidence**.
- The answer uses that evidence.

You can also open Evidence from Changes to select a changed file.

## 6. Test saving and resuming

While idle:

1. Type a question **without submitting it**.
2. Press Esc to save and close.
3. Run:

```text
/bro guided-review resume
```

Select the review.

**Expected:**
- The saved guide and discussion are present.
- The unsubmitted question is retained.
- The reading position is restored.
- Reopening does not generate a new answer.

Then quit Pi, launch it again using the same command from step 1, and repeat `/bro guided-review resume`. This checks persistence beyond the current process.

## 7. Test cancellation

Submit a question, then press Esc while it is running.

**Expected:**
- The response is cancelled.
- The panel stays open.
- Any received partial answer is labelled partial.
- A second Esc, once idle, saves and closes.
- Reopening preserves prior completed work.

Also try cancelling initial guide generation. Captured Changes should remain available, with an explicit retry rather than a falsely completed guide.

## 8. Test terminal sizes

Try approximately:

- **Wide:** 110 columns × 32 rows.
- **Constrained:** 60 columns × 20 rows.

Resize while the review is open.

Check:
- Can you reach the composer and every action?
- Is focus obvious?
- Does typing stay in the composer?
- Do prose and code remain readable?
- Does switching views preserve position?
- Are important controls clipped or confusing?

**Please report awkwardness as well as outright failures.** This is the first UI pass; “technically works but painful to use” is valuable feedback.

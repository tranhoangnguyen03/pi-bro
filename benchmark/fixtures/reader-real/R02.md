## What happened

Your merge **did** release: `npm publish` succeeded at 07:44:44 (`+ pi-bro@0.10.1`, signed provenance). The **next step** then failed:

```
npm does not have 0.10.1; not creating a GitHub release
Error: Process completed with exit code 1
```

Cause: registry read-after-write race. The `npm view` in the release step hit a replica that hadn't caught up with the publish that happened 2 seconds earlier. My bug — I had no retry.

## What I did

1. **Recovered immediately** — re-ran the workflow: tag and npm version already existed, so it skipped both and created the missing release.
2. **Fixed forward** — PR [#36](https://github.com/tranhoangnguyen03/pi-bro/pull/36) (merged as `287495d`): the release step now polls `npm view` for up to 60s before giving up, so a fresh publish never trips this again.

While doing that, strict branch protection also caught a mistake of mine: I branched the fix from a stale local `main`, so its diff silently reverted `package.json`/`package-lock.json` and CI failed with `shipped files changed (package-lock.json, package.json) but package.json is still 0.10.1`. Rebased onto current `main`; CI green. That guard is doing exactly what it's for.

# Claude backend manual E2E (0.16.0)

Load this checkout, not the installed package:

```sh
BRO="$HOME/Github/pi-bro/.worktrees/backend-claude"
TEST="$(mktemp -d /tmp/bro-claude-e2e.XXXXXX)"
printf 'CLAUDE_WORKSPACE_CANARY_6248\n' > "$TEST/sample.txt"
cd "$TEST"
pi --no-extensions -e "$BRO/bro.ts" --no-skills --no-prompt-templates --no-context-files --session "$TEST/session.jsonl"
```

Uses existing Pi/Bro configuration and Claude login. Back up `${PI_CODING_AGENT_DIR:-$HOME/.pi/agent}/bro-settings.json` before changing settings. Claude Code 2.1.281 was live-tested. `--safe-mode` is required; older CLIs should fail with their unsupported-flag diagnostic, not fall back. Claude API/account entitlement controls model and effort availability.

1. `/bro config`: select Claude Sonnet for explain, Claude Opus or a custom ID for advisor; leave Agy as shared default and BTW on Default. Each model picker combines backend+model into one atomic choice. Esc cancels; switching backend resets effort to its default. Explicit edits save version 2 without losing pinned overrides.
2. `/bro text There are two retries, after five seconds and ten seconds.`: modal streams and preserves the numbers. R reruns, C copies, Esc closes, `/bro open` reopens without a new request. Run `/bro file sample.txt` too.
3. Select Claude for show; after two parent conversation turns run `/bro show 2`. Expect conversation visualization, no workspace investigation.
4. `/bro advisor-steer`: save `Begin with STEER_7391. Do not modify files.` Ask parent to call bro_advisor to read sample.txt and report its token. Expect real tool activity, correct token, steering prefix and Claude backend in the result header. No Agy process should handle this consultation.
5. `/bro model` and `/bro effort` change only the shared default, using its backend. Claude accepts aliases/custom IDs and default/low/medium/high/xhigh/max; unsupported model combinations must return Claude's error, not silently clamp or use Agy.
6. Select Claude for BTW. `/bro btw --fresh Remember the token HERON_42.` (header badge `conversation-only`), then ask for the token; close/reopen and ask again: native `--resume` keeps it. Type `/mode` (badge `full permission`), then `Read sample.txt and report its contents; do not modify files.` Expect a real read and the token still remembered (same native session). `/mode` back: the answer comes without tools. `/bro btw --full` must be rejected with a `/mode` hint and nothing sent. Switching BTW to Agy starts a visibly fresh thread; no Claude session ID reaches Agy.
7. `/bro doctor`: effective backend/model/effort per capability; Claude installed/auth configured is distinct from connectivity. `/bro usage` is explicitly Agy-specific.
8. Cancel explain/show/BTW/advisor while running. Expect no late successful result, no retry after cancellation, and immediate usability of subsequent requests (stubborn process cleanup allows five seconds).
9. Reopen config/restart Pi: selections persist. Restore the settings backup after testing if desired.

Privacy expectations: explain/show use safe mode + no tools/MCP/skills and scratch cwd; this is not OS process isolation. BTW uses safe mode in the workspace with session persistence (Claude keeps sessions in its own data directory); conversation-only turns are tool-less, full permission turns bypass permissions. Built-in/managed CLI behavior can remain. Advisor is workspace-enabled, auto-approved and instructed not to edit, not an enforced read-only process. Results from advisor enter the parent tool transcript; modal explanation/show/BTW results do not automatically do so.

Automated evidence: offline Agy and Claude fake-CLI tests, settings migration/unknown-schema checks, existing UI/RPC smoke coverage. Live checks completed with authenticated Claude: tool-less explain returned its exact marker and advisor read package.json and returned 0.16.0. Those checks do not constitute live verification of every model/effort or Windows behavior.
